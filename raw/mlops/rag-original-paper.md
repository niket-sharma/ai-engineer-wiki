# RAG: Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks

**Paper:** "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks"
**Authors:** Patrick Lewis, Ethan Perez, Aleksandra Piktus, Fabio Petroni, Vladimir Karpukhin, Naman Goyal, Heinrich Küttler, Mike Lewis, Wen-tau Yih, Tim Rocktäschel, Sebastian Riedel, Douwe Kiela (Facebook AI Research)
**Published:** 2020-05-22
**arXiv ID:** 2005.11401
**Venue:** NeurIPS 2020

---

## Motivation

**The knowledge problem in NLP (2020):**
- Seq2seq models (T5, BART) parametrize knowledge implicitly in weights
- "World knowledge" (facts, entities, relationships) stored in 11B+ parameter models
- No way to update knowledge without full retraining
- No provenance: model can't cite where it "learned" a fact

**RAG hypothesis:** Augment generation with explicit retrieval over a non-parametric memory (Wikipedia). Let the retriever find relevant documents; let the generator produce the answer conditioned on those documents.

---

## Architecture

### Components

**Retriever (DPR — Dense Passage Retrieval):**
- Two BERT-base encoders: one for questions, one for passages
- Passage encoder encodes all of Wikipedia into a FAISS index
- Query encoder encodes the question at query time
- FAISS inner product search returns top-K passages

```
BERT_q(question) → q_embedding ∈ R^768
BERT_d(passage) → d_embedding ∈ R^768

score(q, d) = q_embedding^T · d_embedding
top-K passages = FAISS_search(q_embedding, K=5)
```

**Generator (BART-large):**
- Seq2seq model: BART with 400M parameters
- Input: question + top-K retrieved passages concatenated
- Output: generated answer

### Two RAG Variants

**RAG-Sequence:**
```
P(y|x) = Σ_{z ∈ top-K} P_η(z|x) · P_θ(y|x,z)^{1/|y|}
```
Each sequence y is generated by marginalizing over retrieved documents. One document is used per generated answer.

**RAG-Token:**
```
P(y_i|x, y_{1:i-1}) = Σ_{z} P_η(z|x, y_{1:i-1}) · P_θ(y_i|x, z, y_{1:i-1})
```
Different documents can be retrieved for different tokens in the output. More flexible but more complex.

**In practice:** RAG-Sequence typically performs better and is easier to implement.

## Training

The retriever and generator are trained **jointly** end-to-end:
- Loss: negative log-likelihood of the correct answer
- Gradient flows through the generator (BART)
- Gradient flows through the retriever query encoder (not the passage encoder — too expensive)
- Passage index is frozen during training (periodically refreshed)

**Key insight:** The retriever learns to retrieve documents that help the generator produce correct answers, even without explicit supervision on which documents to retrieve.

---

## Wikipedia Index

- **English Wikipedia** dump from December 2018
- Chunked into 100-word non-overlapping passages
- **21 million passages** total
- Each passage encoded with BERT into 768-dimensional vector
- Stored in FAISS with IVF index (approximate search)

## Experimental Results

### Open-Domain QA (TriviaQA, NaturalQuestions, WebQuestions)

| Model | TriviaQA | NaturalQuestions | WebQuestions |
|---|---|---|---|
| T5-11B (parametric only) | 36.6% | 34.5% | 37.4% |
| DPR (retriever only, extractive) | 57.9% | 41.5% | 42.4% |
| RAG-Sequence | **56.8%** | **44.5%** | **45.5%** |

**Key result:** RAG with 400M BART + retrieval outperforms T5-11B (10B parameters) on NaturalQuestions. Retrieval beats raw scale for knowledge-intensive tasks.

### Abstractive QA (MS-MARCO NLG)

RAG achieves new SOTA on MS-MARCO Natural Language Generation task, outperforming extractive approaches.

### Jeopardy Question Generation

Task: Given an answer, generate the Jeopardy question.

Human evaluation showed RAG generates more factual, specific, and diverse questions than pure parametric models.

### Factual Correctness (FEVER)

RAG models produce more factually grounded text — 11.9% reduction in hallucinations vs parametric-only generation.

## Key Insights from the Paper

### 1. Retrieval Provides Grounding

RAG models hallucinate less because the generator is conditioned on retrieved text. The model can essentially "copy" from the retrieved document rather than relying on noisy memorized facts.

### 2. Retrieval Enables Updatability

To update world knowledge: swap out the Wikipedia index for a new dump. No retraining required. This is a fundamental advantage over purely parametric models.

### 3. Hybrid Parametric + Non-Parametric Memory

The BART generator still has implicit knowledge (syntax, reasoning, common sense) while the retriever provides explicit factual knowledge. The best of both worlds.

### 4. DPR vs BM25

The paper shows dense retrieval (DPR) outperforms BM25 for most questions except those with rare entities or exact-match requirements. Hybrid approaches (dense + sparse) are mentioned as promising future work.

## Limitations Identified

1. **Chunking:** Fixed 100-word chunks may split answers across chunks
2. **Retrieval latency:** FAISS search adds ~50ms per query
3. **Max K passages:** Context window limits how many passages can be concatenated
4. **No multi-hop reasoning:** Single-step retrieval misses questions requiring reasoning across multiple documents
5. **Domain mismatch:** Wikipedia-trained retriever may not work well in specialized domains

These limitations directly motivated subsequent work:
- Multi-hop QA (HotpotQA approaches)
- Advanced chunking (hierarchical, semantic)
- Iterative retrieval (IRCoT, Agentic RAG)
- Domain-specific fine-tuning

---

## Why This Paper Matters (2024 Perspective)

This 2020 paper defined the template that virtually every production RAG system follows:
1. Offline: chunk documents, embed, store in vector index
2. Online: embed query, retrieve top-K, concatenate with query, generate

All subsequent RAG work (Advanced RAG, Self-RAG, CRAG, Agentic RAG) is building on this foundation.
